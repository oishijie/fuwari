前阵子读到威言威语的一篇博客：《[十九年后，我第一次跳出自己的舒适区](https://www.weisay.com/blog/119-years-later-i-changed.html)》。

作者说自己写博客超过十九年，主题换过不少，但回头一看，十九年清一色都是双栏布局——侧边栏、分类、标签、最新评论、归档，一个不少，规规矩矩。他突然意识到，那不是什么设计底线，是一种待了十九年的舒适区。

这次改版，他第一次认真做了个单栏主题。问自己的问题是：

> 如果没有侧边栏，会怎么样？如果整个页面只剩下文章，它还能不能成立？如果把功能放到第二位，把阅读放到第一位，又会是什么样？

说实话，这几个问题像针一样，把我一直想动、又总找借口没动的侧栏给挑了出来。

上篇《换掉那只紫鸟》折腾完头像和签名，看着顺眼了，可侧栏还是老样子：左边一整条常驻，正文被挤在右边一窄条里。我自己写东西的时候，明明最该被看见的是文章，结果视觉重心全在左侧那一堆模块上。

于是这轮折腾，就从这根针开始。

## 第一步：让侧栏默认折叠

原布局是 `grid-cols-[17.5rem_auto]`，左边 17.5rem（280px）的侧栏常驻，正文占剩下的 `auto`。

我的目标很简单：**打开文章页，侧栏默认折叠，正文吃满 `--page-width`（1168px）；想看的，自己点开。**

为此在 `MainGridLayout.astro` 里加了一个状态机，由 `<html data-sidebar>` 这一个属性统一驱动：

- `collapsed`：第一列收成 `0px`，卡片吃满整宽，侧栏淡出隐藏（默认）
- `expanded`：用户手动展开
- `off`：本页不适用（首页 / 归档 / 关于），保持原双栏

```css
@media (min-width: 1024px) {
  html[data-sidebar="collapsed"] #main-grid {
    grid-template-columns: 0px auto;
    column-gap: 0;
  }
  html[data-sidebar="collapsed"] #sidebar {
    visibility: hidden;
    opacity: 0;
    pointer-events: none;
  }
}
```

几个容易踩的坑，这轮都提前堵了：

1. **首屏闪烁**：状态必须在网格绘制之前同步写入 `<html>`，否则会先按双栏画一帧再跳变。所以那段设置 `data-sidebar` 的脚本放在 `main-grid` 之前、而且是同步执行的。
2. **Swup 不重建侧栏**：本站无刷新导航只替换 `main` 和 `#toc`，侧栏和开关按钮不在替换范围里。切页后得手动重算状态——挂了 `astro:page-load` / `swup:page:view` / `content:replace` 三个时机兜底。
3. **偏好记忆**：展开/折叠状态存 `sessionStorage`，一次展开，本会话内翻其他文章不再弹回折叠。
4. **移动端不参与**：`<1024px` 本就是单列堆叠，折叠逻辑只在大屏生效，死按钮不会出现。

开关是一个贴在正文左缘外侧空白区的小箭头，半透明，hover 才实。展开后箭头转 180° 提示"点我收起"。

## 第二步：收窄阅读列，拆一个"伪约束"

折叠之后，正文一下吃到 1168px。量宽太宽了——大约 73 个汉字一行，读起来眼睛要横向扫很长的距离。

我想收窄。但又犯嘀咕：**窄了之后，正文不是就跟顶部导航栏不对齐了吗？**

这个担心，其实是把两个东西混为一谈了。

顶栏的对齐线，对齐的是**卡片的外缘 1168px**，不是正文里的文字量宽。展开态下，正文卡片左右各有 36px 内边距，真正写字的地方只有 872 − 72 = 800px。也就是说，"顶部 1168、正文 800"本来就是同时成立的，从来没"对齐"过。

所以正确的减法不是去动卡片外缘，而是**只把卡片内部的文字列收 800px 并居中**，卡片外缘纹丝不动：

```css
:root { --read-width: 50rem; }  /* 50rem = 800px */

html[data-sidebar="collapsed"] #post-container {
  padding-left:  max(1.5rem, calc((100% - var(--read-width)) / 2));
  padding-right: max(1.5rem, calc((100% - var(--read-width)) / 2));
}
```

`padding` 的百分比基准是包含块宽度（= 正文列宽），所以 `(100% − 800px) / 2` 正好把富余宽度左右平分。折叠 / 展开切换时，正文量宽恒为 800px，只是整列左右滑动，不突兀。

这里还藏一个坑：**故意不给 padding 加 transition**。因为 padding 是"跟随容器宽度"现场算出来的，逐帧代入可得正文量宽 ≡ 800px 是恒定的；一旦写成过渡，两端做插值反而会在动画中点鼓到 874px，文字来回重排。不写过渡，它自己就是稳的，而且不会覆盖 `.card-base` 的主题切换淡入。

想更窄改一个数字就行：`46rem` ≈ 46 汉字/行，`42rem` ≈ 42 汉字/行。

## 第三步：顺手修了个真 bug

折腾侧栏的时候，顺手发现一个藏了很久的真问题：**整站 favicon 静默失效**。

翻 `src/config.ts`，`favicon` 还指向 `imgbed.142588.xyz` 那个图床。而那个域名后来 DNS 整体失效了。问题在于，`siteConfig.favicon` 只要非空，就会覆盖 Fuwari 默认的那套本地 favicon——结果就是整站图标静默加载失败，浏览器退回空白页图标，谁都看不出哪儿错了。

修法很朴素：把 `favicon` 置空，走主题自带的 `public/favicon/*.png`（亮/暗两套 × 32/128/180/192），零外部依赖。顺带把那套默认图标换成站点主题色的"留"字圆角方标。

```ts
// 留空 = 使用 src/constants/icon.ts 里的 defaultFavicons：
// 本地 public/favicon/*.png（亮/暗两套 × 32/128/180/192），零外部依赖。
favicon: [],
```

这个故事的教训记下来了：**凡是会覆盖默认值的外链资源，域名一旦失效就是全局静默故障**。图床外链能不用就不用，图标这种高频小资源尤其该本地化。

## 收尾：博客永远不会真正完成

威言威语在文末写：

> 双栏也好，单栏也好，其实都只是表现形式。真正没有变的，还是我写博客的初衷。……一个博客最大的乐趣，大概就是它永远没有真正完成的时候。

这轮折腾的起点，是别人一篇写了十九年的博客；终点，是我自己屏幕上更安静的一栏文字。

侧栏折起来之后，首页、归档、关于那些"功能型"页面该双栏还双栏——减法不是为减而减，是让文章页把注意力还给文章。至于阅读列定在 800 还是 750，过阵子读到什么、自己读着顺不顺，大概还会再调。

毕竟，和十九年比，我才刚上路。
