> 你能看到这段文字，说明密码输入正确。**本篇正文在页面源码里只是一串 Base64 密文**——没有密码的人，连一个字都读不到。

## 这一篇是干什么用的

它是「加密文章」功能的示例。在你滚动之前，可以先做一个小实验：**右键 → 查看网页源代码，然后搜「加密」两个字**。正文里一个都搜不到，只有一段 Base64 字符串。

这顺便说明了一件事：加密保护的是**正文**，文章的**标题**（首页卡片、归档、浏览器标签页、RSS 标题）依然是公开的。加密不是"让这篇文章消失"，而是"不让人读到内容"。

## 怎么给一篇文章上锁

在这个博客里，只需要在 frontmatter 里加一行 `password`：

```yaml
---
title: 一篇不想公开的文章
published: 2026-09-13
password: "你的口令"
passwordHint: "提示语，会显示在密码框下方（可选）"
---
```

`password` 一出现，构建流程就会把渲染好的正文 HTML 加密，页面里只留密文。把这一行删掉，文章立刻恢复公开。

## 它是怎么工作的

| 环节 | 做法 |
|---|---|
| 加密时机 | **构建时**（`astro build`），不在浏览器里做 |
| 加密算法 | AES-256-GCM（带认证标签，密文被篡改会解密失败） |
| 密钥派生 | PBKDF2-SHA256，**10 万次**迭代 |
| 密钥来源 | 你自己填的 `password`，**从不发往任何服务器** |
| 解密地点 | 访客的浏览器（Web Crypto API） |
| 记忆方式 | `sessionStorage`，同一标签页会话内免二次输入，关掉浏览器即失效 |

密文的组成是 `Base64(salt + iv + authTag + ciphertext)`。其中 salt 与 iv 不是随机的，而是由 `HMAC-SHA256(密码 + 文章标识)` **确定性地**推导出来——否则每次构建密文都会变，浏览器里缓存的密码就再也对不上了。

## 几个刻意的取舍

- **目录不生成**。目录是从标题文本生成的，如果不屏蔽，加密文章会在侧栏把各级标题大白于天下。所以锁定状态下目录是空的，解锁之后才重建。
- **评论自动隐藏**。文章都锁着，评论区没有存在的意义。
- **RSS 不输出正文**。订阅阅读器里只会看到标题和描述，正文为空——否则等于绕开密码把全文公开。
- **首页卡片摘要为空**。这是最容易被忽略的一条：卡片摘要原本会回退取正文第一段，对加密文章必须掐掉，否则首页就把第一段贴出来了。
- **建议写 `description`**。不写也能正常看，只是首页卡片上除了标题什么都没有；写的话请避免敏感信息，因为它是公开的。

## 顺手验证一下渲染

解锁后的 HTML 是**解密之后再注入**的，所以那些依赖 DOM 的增强功能（图片灯箱、代码块复制、公式渲染）都要重新跑一遍。下面这张图和这段代码就是拿来验证它们的：

![加密示意](https://images.unsplash.com/photo-1518770660439-4636190af475?w=1200&q=80)

```javascript
// 解密的核心三步（浏览器端，简化自本项目实现）
const key = await crypto.subtle.deriveKey(
  { name: "PBKDF2", salt, iterations: 100000, hash: "SHA-256" },
  keyMaterial,
  { name: "AES-GCM", length: 256 },
  false,
  ["decrypt"],
);

const plain = await crypto.subtle.decrypt({ name: "AES-GCM", iv }, key, combined);
```

### 如果图片能点开灯箱、代码块右上角有复制按钮

那说明解密后的重新初始化是正常的——点一下右上角的复制按钮试试。
